# 0001 迁入源码仓与四层拆分

- **日期**：2026-11-08
- **状态**：已接受
- **背景**：项目 85 的 C 阶段产物原本落在 `D:/Ai-Files/Projects/85-配乐提示词生成器/`，形成一处混装：源码、构建脚本、369MB Electron 运行时、运行态、导出产物、两处重复的 `selfcheck.json` 全挤在 `app/` 一层，无可双击成品、无版本号、无目录契约。人类裁定按「开发中的源码」归位，而非当作可交付成品。
- **决定**：
  1. 源码迁入 `D:/Ai-Files/Repos/GitHub/score-prompt-generator/`，按 `STRUCTURE.md` 分 `src/`（main／preload／renderer）、`scripts/`、`config/`、`build/`、`tests/`、`docs/adr/`、`assets/`。
  2. 三处硬编码绝对路径改为相对仓根解析：`build.py` 的 `OUT`、`render.py` 的 `BASE`、`main.js` 的 `CLI_ROOT`。
  3. 配置拆双层：`config.example.json` 入库只放模板，`config.local.json` 存本机实值并忽略；`state_home` 决定运行态与导出落点。
  4. 运行时二进制（`runtime/electron/`，369MB）不进仓，改由本机 Electron 缓存解压或 npm 安装提供；启动器只负责定位。
  5. 运行态与导出（`.runtime/`、`exports/`、`selection.json`、`selfcheck.json`）留在仓外状态目录，不入库。
- **后果**：
  - 源码仓体积从约 369MB 降到数十 KB 级，可跨机同步、可提交版本库。
  - 换机需先备运行时（缓存解压或 `npm install`），首次启动多一步。
  - 运行 `scripts/build.py` 才能重建 `build/data.js`；`build/` 已忽略，不随仓走。
  - 派生的 `render.py` 缺 Baseline 时，13 份模板零改写检查如实标「未执行」，不再静默放行（原实现在基线缺失时直接抛异常）。
- **执行结果（2026-11-08 回填）**：
  - 建仓完成，初始提交 `fd53374`（17 文件、405KB）。
  - 三轮真启动冒烟：首轮「契约未通过」经逐项复现，根因是库内 3 份模板 md 在 11-06 构建后被改写（与迁仓无关）；重跑 `scripts/build.py` 后契约四项全过，终轮 `26 PASS／0 FAIL`。
  - `app/runtime/`（369MB、73 文件）已经 `SHFileOperationW`＋`FOF_ALLOWUNDO` 送回收站（返回 0、目标消失、回收站新增 74 条），可撤销。
  - 旧源码副本与派生数据 18 个文件已删除，旧目录降至 212KB，仅留运行态与导出。
  - 本会话 `capturePage()` 因环境无可用显示面返回失败，未重出截图；跨机与远端仓库未验证。
- **待复核**：① 本仓尚无 remote，是否建远端并推送待人工决定；② C 阶段收官（完整 15 栏目界面）后再决定是否打包进 `Tools/Exe/`，届时另立 ADR；③ 回收运行时后，本机运行需先从 `%LOCALAPPDATA%/electron/Cache` 的 `electron-v44.9.3-win32-x64.zip` 解压或 `npm install`。
